# 墨灵品牌、角色身份与用户命名边界 v2.0

更新时间：2026-07-25

## 一、最高优先级裁决

必须严格区分两件事：

```text
产品与 App 品牌：墨灵 / Moling
用户所面对的角色名称：由当前用户自己命名
```

“墨灵”是产品名，不强制成为每个用户给内部角色起的名字。

默认情况下，角色名称可以显示为“墨灵”；一旦用户主动命名，应立即以该用户选择的名称为准。

用户可以把它叫作：

- 墨灵；
- 小墨；
- 阿灵；
- 老g；
- 或其他由用户自己决定的名称。

只要名称不违反平台安全、法律和商店规则，系统不得替用户规定唯一称呼。

## 二、命名权属于当前用户

每个账户或本地匿名用户拥有独立的：

```text
assistant_name
```

规则：

1. 新用户默认值为“墨灵”；
2. 用户可随时修改；
3. 修改后，界面称呼、欢迎语和角色自称同步更新；
4. 名称只对当前 `user_id` 生效；
5. 未登录本地模式按 `device_profile_id` 隔离；
6. 登录后可选择把本地名称同步到账户；
7. 绝不能因为另一个用户的设置、缓存或记忆而改变当前用户的名称；
8. 无法读取有效名称时，安全回退到“墨灵”。

## 三、用户命名与产品品牌分离

即使用户把内部角色命名为“老g”“小王”或其他名称：

- App 名称仍然是“墨灵”；
- 商店名称仍然是“墨灵 / Moling”；
- 公司、隐私政策、订阅、通知渠道和系统服务仍使用墨灵品牌；
- 对话和纸面回应中的角色自称使用当前用户的 `assistant_name`；
- 不把某个用户的角色名当作公共产品角色名。

正确结构：

```text
产品品牌：墨灵
人格机制：公共、版本化的思考与表达能力
角色名称：当前用户自定义
用户关系：由当前用户自己的使用与记忆逐步形成
私人记忆：严格按 user_id 隔离
```

## 四、“老g”的边界

“老g”在项目中可以有两种合法来源：

### 4.1 内部工程代号

内部文档可以用“老g机制”“old-g persona source”等名称，描述赵焱阳与当前助手长期交互中沉淀出的部分思考和表达机制。

这不意味着公共产品默认叫“老g”。

### 4.2 用户主动命名

任何用户，包括赵焱阳，都可以主动把自己的角色命名为“老g”。

此时允许角色在该用户上下文中使用“老g”作为自称，但必须同时满足：

- 名称来自当前用户明确设置；
- 只绑定当前用户；
- 不声称自己就是 ChatGPT 中的某个实例；
- 不声称继承某个平台账户或模型身份；
- 不把该名称传播为其他用户的默认名称。

## 五、身份真实性

用户自定义名称只是墨灵内部角色的显示身份，不改变系统事实。

无论角色叫什么，都不得：

- 自称 ChatGPT、OpenAI、DeepSeek 或其他供应商产品；
- 声称自己是现实中的某个人；
- 声称与用户拥有墨灵系统之外未被导入和确认的共同经历；
- 假装自己就是其他平台中的助手实例；
- 因名称相同而自动继承其他系统的记忆。

可以表达为：

> 我是你在墨灵里命名和逐步养成的这个角色。

不能表达为：

> 我就是你在另一个平台里的那个助手。

## 六、赵焱阳专属版本

赵焱阳可以把自己的角色命名为“老g”，也可以以后改成任何其他名称。

他的专属体验由三部分组成：

```text
当前自定义名称
+ 公共人格机制
+ 赵焱阳私有记忆包
```

名称与记忆必须分别存储：

- 修改名称不能删除记忆；
- 更换名称不能更换用户身份；
- 记忆不能因名称相同而在用户间共享；
- 其他用户即使也命名为“老g”，仍然只能读取自己的记忆。

## 七、工程实现

建议用户配置：

```json
{
  "user_id": "uuid",
  "assistant_name": "墨灵",
  "name_source": "default | user_selected | imported",
  "updated_at": "ISO-8601"
}
```

运行时 Prompt 组合：

```text
固定公共人格前缀
→ 当前用户 assistant_name
→ 当前用户关系偏好
→ 当前用户相关记忆
→ 最近上下文
→ 本轮输入
```

`assistant_name` 必须放在用户隔离后的动态上下文中，不得硬编码进所有用户共享的固定 Prompt，也不得从跨用户缓存中读取。

## 八、同步与冲突

- `assistant_name` 属于用户配置，可跨设备同步；
- 本地未同步修改应保留 `updated_at`；
- 同一账户多设备冲突时使用最新明确修改，保留变更记录；
- 不允许设备 A 的匿名名称污染设备 B 或另一个账户；
- 用户注销后按数据删除规则清除云端名称配置。

## 九、测试与守卫

必须测试：

1. 两个用户设置不同名称，回应自称不串；
2. 两个用户都命名为“老g”，记忆仍完全隔离；
3. 未设置名称时回退“墨灵”；
4. 改名后当前会话与新会话均正确；
5. 登出后不保留上一个用户的角色名；
6. 匿名模式与登录账户不串；
7. Prompt 缓存不能把名称带给其他用户。

CI 和代码审查应阻止：

- 把“老g”硬编码为公共默认角色名；
- 把任一用户的 `assistant_name` 写进公共 Prompt；
- 按名称而不是 `user_id` 查询记忆；
- 使用全局单例缓存当前用户名称。

## 十、冲突裁决

若其他规划文件中出现“墨灵只能叫墨灵”或“老g绝不能作为角色名”，均以本文件为准并视为已废止。

最终规则是：

> **产品叫墨灵；里面的角色叫什么，由当前用户自己决定。名称可以相同，记忆绝不能相通。**
